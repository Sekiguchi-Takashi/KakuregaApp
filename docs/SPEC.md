# カクレガ（仮）仕様書 v0.1

探索型ファイル保管アプリ。仮想の家をコマ送り（静止画シーン遷移）で探索し、家具をタップしないとファイルにたどり着けない。ファイル管理そのものをアドベンチャーゲーム化することで、隠匿性と楽しさを両立する。

- リポジトリ: KakuregaApp
- パッケージ: com.appathy.kakurega
- アプリ名: カクレガ
- 方針: 依存ゼロ・プログラマティックUI（Compose不使用、BunsanAppと同方針）、AGP 8.5.2 / Kotlin 1.9.24 / Gradle 8.9
- パーミッション: v1.0はゼロ。LAN連携フェーズで INTERNET / ACCESS_WIFI_STATE を追加

---

## 1. 中核概念（オントロジー）

| 実体 | 説明 |
|---|---|
| シーン | 1枚の静止画（部屋の一視点）。タップ領域を持つ |
| ホットスポット | シーン上の矩形/多角形領域。遷移・収納・アイテム・錠のいずれかに対応 |
| 収納スロット | ファイルを置ける場所（引き出し・ステレオ・本棚・金庫など）。種別ヒントを持つ |
| アイテム | 鍵など。入手するとインベントリに入り、錠の解除条件になる |
| 錠 | 収納スロットを守る条件。種別: なし / 鍵アイテム / PIN / 分散片 / LANペア |
| 保管ファイル | アプリ内領域に取り込まれた実ファイル。スロットに紐づく |

家＝シーングラフ。シーングラフは assets/house.json で定義し、後から画像とJSONを差し替えるだけでテーマ変更できる構造にする。

## 2. フェーズ計画

### Phase 1（v1.0）ベース
1部屋・固定画像・家具5種で「探索してファイルを出し入れする」体験を成立させる。

- シーン: リビング1枚（仮画像。単色背景＋家具シルエットの自前描画でも可）
- 収納スロット5種: 引き出し（画像）/ ステレオ（音楽）/ 本棚（PDF・テキスト）/ テレビ台（動画）/ 床下（その他）
  - 種別はあくまでヒント。どのスロットにも任意ファイルを置ける
- 操作フロー:
  - スロットをタップ → 中身一覧（ファイル名・サイズ・日時）
  - 「しまう」= ACTION_OPEN_DOCUMENT で取込 → filesDir/vault/ にランダム名でコピー → 台帳に記録
  - 「見る」= 画像/テキストは内蔵ビューア、音楽/動画は内蔵再生（MediaPlayer）
  - 「取り出す」= ACTION_CREATE_DOCUMENT で書き出し
  - 「燃やす」= アプリ内から完全削除（確認ダイアログ）
- 隠匿の基本: vault内は拡張子なしランダム名＋.nomedia。原本の削除はSAFの権限上できないため自己申告（BunsanAppと同じ整理）
- 台帳: SQLite（android.database.sqlite 直用）。files(id, slot_id, orig_name, mime, size, added_ts, stored_name)
- コマ送り演出: シーン遷移は即時切替＋短いフェード。効果音なし（後回し）

### Phase 2（v1.x）家の拡張と画像差し替え
- シーンを複数化（玄関→廊下→リビング→書斎→2階）。矢印ホットスポットで移動
- house.json を editable 化: 画像を端末から選んでシーンに割り当て、画面上を長押しドラッグでホットスポット矩形を自分で引ける「増築モード」
- 額縁の裏・カーペットの下など「見えないホットスポット」対応（増築モードでのみ枠が見える）
- スロット追加・部屋追加＝フォルダ増設に相当

### Phase 3（v2.0）錠システム
すべての錠は lock(type, params) としてスロットに付与する統一設計。

- 鍵アイテム錠: 家のどこかのホットスポットに鍵を配置（自分で置き場所を決める）。入手→インベントリ→対象スロットに使用。鍵の配置自体が自作の謎解き導線になる
- PIN錠: 4〜8桁。金庫のダイヤルUI。試行間隔を指数バックオフ（5回失敗で30秒→倍々）
- 分散片錠: BunsanApp の .bnsn 片をスロットに置ける（BNSNヘッダを読み取り専用でパースし k-of-n と x を表示）。「金庫の中身は片で、家中から k 個集めないと意味を成さない」という遊び方。復元処理自体は BunsanApp に委ね、カクレガは片の保管と書き出しのみ担当（FORMAT_SPEC.md準拠の読取のみ実装、二重実装しない）
- LANペア錠: 下記

### Phase 4（v2.x）LANペア解錠
同じWi-Fi内のもう一台のカクレガと握手できたときだけ開く錠。

- 発見: NSD（NsdManager、_kakurega._tcp）で相互発見。パーミッション追加最小
- 握手: ペア設定時に両端末で共通シークレットを生成し分割保持（端末Aに秘密a、端末Bに秘密b、錠は H(a||b) を保存）。解錠時はローカルソケットで b を受け取り検証。シークレットは平文をネットワークに流さずチャレンジレスポンス（HMAC）にする
- ペア設定の受け渡しは同一画面に表示する6桁確認コードの目視照合（QRやカメラ権限を増やさない）
- ユースケース: 家族の2台が揃わないと開かない金庫／メイン機とサブ機の二要素化

## 3. house.json スキーマ（v1）

- scenes[]: { id, image(assets名 or vault内), hotspots[] }
- hotspot: { rect[x,y,w,h]（画像座標系0..1の比率）, kind: goto|slot|item, target }
- slots[]: { id, name, hint_mime, lock: { type: none|key|pin|bnsn|lanpair, params } }
- items[]: { id, name, placed_at(hotspot id or "inventory") }
- version フィールド必須。旧版読取は永久維持（BunsanAppの不変条件を踏襲）

## 4. 画面一覧（Phase 1）

1. シーン画面（メイン）: 全画面画像＋タップ判定。長押しでホットスポット枠を一瞬表示（見失い防止、設定でOFF可）
2. スロット内一覧: ファイルリスト＋しまう/見る/取り出す/燃やす
3. ビューア: 画像（ズーム可）/ テキスト / 音楽・動画（最小コントロール）
4. 設定: 枠ヒント表示、増築モード（Phase 2で有効化）

## 5. セキュリティの割り切り（明記事項）

- 本アプリの防御線は「見つけにくさ」＋「錠」。root化端末や adb でのvault直読には暗号化なしでは無力。ファイル単位の真の秘匿が必要な場合は BunsanApp の分散片にしてから置く、が公式の答え
- vault暗号化（端末内鍵でのAES）は将来オプション。入れる場合も「鍵を失うと全損」問題があるため既定OFF
- FLAG_SECURE（スクショ防止）はビューアのみ既定ON

## 6. ビルド・納品規約（Appathy共通）

- deploy.sh 恒久仕様（pull --rebase＋タグ自動採番・発行）をリポジトリ直下に同梱
- .github/workflows/release.yml と ci/ はカタログ管理システムが注入するため削除しない
- build.yml は workflow_dispatch のみ・upload-artifact なし（コンパイル確認専用）
- 納品はバージョン番号付きZIP、実行手順は固定4行

## 7. Phase 1 の受け入れ条件

- 画像1枚の部屋で5スロットが動き、取込→閲覧→書出→削除が一巡できる
- vault内のファイルがファイラーやギャラリーから見えない（.nomedia＋ランダム名）
- アプリ再起動後も台帳とスロット内容が保持される
- 権限要求ゼロのままインストール・動作する

## 改訂 v0.2

- 錠システムの設計は docs/ONTOLOGY.md（錠オントロジー）を正とする。Phase 3の錠型列挙は「条件式（AND/ORの木）＋秘密の所在＋攻撃者クラス診断」に置き換え
- Phase 1 実装（v1.0）: 部屋は自前Canvas描画のSceneView（画像アセットなし）。床下は隠しホットスポットとして実装済み（長押しヒントでのみ枠表示）

## 改訂 v0.3（Phase 3 実装）

- 錠は条件式のDNF表現（OR枝の集合、各枝はANDの要素列）として Lock.kt に実装。SlotDef.lock に埋め込み house.json に保存
- 解錠要素: 隠し場所 / 鍵アイテム / 暗証番号 / 分散片 / 二台目の端末（後者はPhase 4）
- 診断は LockRules.diagnose(Lock) の純粋関数。攻撃者クラスA1〜A4への防御可否、実効強度を決める最弱枝、締め出しリスク、UNDECIDABLE、是正案を返す。起動時 selfTest 10ケース
- 分散片錠は端末に取り込まない。開けるときだけ ACTION_OPEN_DOCUMENT で片を選び、BNSNヘッダの id と x だけを読んで異なる x が k 個そろえば開く。復元処理は行わない（BunsanApp の担当）
- 暗証番号は SHA-256(salt|pin) を salt:hash 形式で保存。5回失敗から30秒→倍々（上限1920秒）のバックオフを SharedPreferences に記録
- 鍵アイテムは house.items に持ち、at にホットスポットidを入れて家のどこかに置く。そのホットスポットを調べると入手しインベントリへ
- 解錠状態はプロセス内のみ保持（アプリを閉じると再度要求）

## 改訂 v0.4（Phase 4 実装）

LANペア解錠を Lan.kt に実装。秘密を二台に割って持たせる。

- ペア設定で a / b / c を生成する。a は錠を持つ側だけ（錠の param に入る）、b は鍵になる側だけ、c は両方（通信路の保護専用）
- 錠に保存するのは SHA-256(a||b) のみ。b はこの端末のどこにも無い
- 解錠は乱数 N を送り、相手が E = b XOR HMAC(c, N) を返す。こちらは c から b を復元し SHA-256(a||b) を照合
- 盗聴者は c を持たないので E から b を取り出せない。仮に b を得ても a はこの端末の中なので b 単体では開かない
- 相手の発見は NSD（_kakurega._tcp）。ペア設定時は6桁の確認番号を両端末に出して目視照合（カメラ権限を増やさない）
- 権限は INTERNET と ACCESS_NETWORK_STATE の2つ。位置情報は使わない
- 正直な限界: 同じWi-Fiにいて両方の端末を触れる相手（A4）は防げない。診断表もそう出す
